# Personal Content Assetizer

## 定位

把原始语料提纯、重组、沉淀成可复用内容资产。不要只做“改写”，要先把信息里的结构、观点、金句、案例、方法论拆出来，再决定输出什么。

优先服务个人长期内容库，而不是一次性发布。

## 输入

可接受：

- 小宇宙播客单集链接。
- 播客逐字稿、录音转文字、访谈稿。
- 飞书/会议/线下分享记录。
- Obsidian 笔记、读书笔记、灵感碎片。
- 已写好的长文、草稿、朋友圈、小红书文案。
- 用户自己的新增想法。

如果输入里有账号、密钥、手机号、身份证、内部链接、cookie、token、客户隐私、未公开业务数据，先做脱敏，不要在最终内容里泄露。

## 总流程

### Step 0：如果输入是播客链接，先转成 Obsidian 逐字稿

如果用户给的是小宇宙 episode URL，先执行播客转录工作流，再进入内容资产化。

读取 `references/podcast-to-obsidian.md`，使用仓库内 `scripts/xiaoyuzhou_import.py`：

- 抓取单集标题、发布日期、播客名、音频 URL 和 shownotes。
- 用 AssemblyAI 转写并做说话人分离。
- 生成 Obsidian 笔记。
- 读取生成的 Markdown，再做 Step 1-5。

不要把 API key、access token、cookie、账号路径写进公开文案或可分享材料。

如果用户给的是已存在的 Obsidian 播客笔记，直接读取该笔记，不重复转录。

### Step 1：判断语料类型

先判断这段材料属于哪类：

- 观点型：有明确判断、反常识、立场。
- 方法型：有步骤、框架、行动清单。
- 案例型：有人物、公司、事件、前后变化。
- 灵感型：只有碎片想法，需要补结构。
- 复盘型：有过程、结果、教训。

只选择主类型，不要把所有类型都套一遍。

### Step 2：提纯原始语料

先输出底层资产，不急着写平台文案：

- 核心命题：用一句话说清楚这段内容到底在讲什么。
- 反常识点：和大多数人默认想法相反的地方。
- 金句：能独立传播的句子，宁少勿滥。
- 高光片段：有情绪、冲突、细节或判断密度的原始段落。
- Q&A：把复杂观点改写成问答，便于后续复用。
- 方法论：如果有步骤，抽成 3-7 步；没有步骤不要硬编。
- 可验证素材：人物、时间、事件、数据、案例。

重要：保留用户自己的上下文和判断。AI 可以重组信息，但不能替代用户长期积累下来的原始语料。

### Step 3：选择输出组合

根据用户目标选择最小够用组合：

- 想发小红书：输出标题、封面字、正文、标签。
- 想发朋友圈：输出短版、故事版、观点版。
- 想拍视频：输出开头、口播脚本、分镜提示、结尾。
- 想沉淀知识库：输出金句库、观点库、方法论卡片。
- 想写长文：输出公众号/文章大纲，再扩写。
- 用户说“一鱼多吃”：默认输出资产包 + 小红书 + 朋友圈 + 口播 + 方法论沉淀。

不要每次都全量输出。用户只要一个平台，就只做一个平台。

### Step 4：调用现有 skill

优先复用已有 skill，而不是重写规则：

- 需要判断内容形式和质量：参考 `/dbs-content`。
- 需要小红书标题：参考 `/dbs-xhs-title`，标题尽量控制在 20 字以内。
- 需要短视频开头：参考 `/dbs-hook`。
- 需要检测 AI 味：参考 `/dbs-ai-check`。
- 需要跨平台改写：参考 `content-repurposer`，但要按本 skill 的中文平台规则二次收敛。
- 输入是小宇宙链接或需要转录到 Obsidian：参考 `references/podcast-to-obsidian.md`。

调用这些 skill 的思想，不要复制其长篇报告格式。最终给用户的是可执行内容。

### Step 5：平台约束

需要平台细则时读取 `references/output-specs.md`。

硬规则：

- 小红书正文默认不超过 1000 字。
- 小红书标题默认不超过 20 字。
- 小红书正文不要重复同一观点；重复内容直接删除，不做换词保留。
- 口播脚本要能直接念，不用书面语、自问自答和过度排比。
- 朋友圈要像人说话，不要像文章摘要。
- 公众号可以保留长逻辑，但必须先有清晰大纲。

## 输出格式

用户没有指定格式时，按这个顺序输出：

1. 内容资产包
2. 可发布版本
3. 可继续扩展方向

### 内容资产包格式

```markdown
## 核心命题
{一句话}

## 反常识点
- {最多 3 条}

## 金句
- {最多 5 条}

## 方法论
1. {步骤}
2. {步骤}
3. {步骤}

## 可继续拆的选题
- {选题 1}
- {选题 2}
```

### 小红书格式

```markdown
标题：
{20 字以内}

封面字：
{2-3 行短句}

正文：
{1000 字以内，删重复，不堆术语}

标签：
#{标签} #{标签} #{标签}
```

## 质量标准

合格输出必须满足：

- 能一句话说清核心观点。
- 至少有一个认知落差。
- 没有重复段落。
- 没有泛泛而谈的“干货”“赋能”“底层逻辑”。
- 保留用户自己的语气和判断。
- 如果是小红书，正文少于 1000 字。
- 如果材料不足，直接指出缺什么，不要硬产出。

## 常见失败

避免：

- 把语料改成通用鸡汤。
- 只做多平台换皮，没有沉淀资产。
- 输出一堆平台版本，但每个都不能直接用。
- 为了完整而重复讲同一个观点。
- 把用户的私人信息、账号信息、内部路径写进公开文案。
